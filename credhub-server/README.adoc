= CredHub server

This directory contains artifacts that can be used to start UAA and CredHub servers that can be used to run tests against.
It is derived https://github.com/orange-cloudfoundry/credhub-docker and https://github.com/ampersand8/credhub-docker.

From the root of this directory, start the servers using Docker Compose:

[source,bash]
----
$ docker-compose up
----

Add `-d` to run the containers in the background (`docker-compose up -d`) so you can keep using the same terminal.

This starts three containers: `uaa`, `credhub` (the default CredHub server, backed by the actively-maintained `pcfseceng/credhub` image, currently CredHub 2.6.0+), and `credhub-v1` (the older, frozen `ampersand8/credhub` image, kept around solely to test pre-2.0 behavior — see below). After they've started successfully, UAA will be available at `http://localhost:8080/uaa`, the default CredHub server at `https://localhost:9000`, and the legacy v1 server at `https://localhost:9001`.

You can confirm they're ready with:

[source,bash]
----
$ curl http://localhost:8080/uaa/.well-known/openid-configuration
$ curl --cacert credhub-v2-certs/server_ca_cert.pem https://localhost:9000/info
$ curl -k https://localhost:9001/info
----

(`-k` is needed for the `credhub-v1` check because it uses a fixed, pre-baked self-signed certificate whose CA isn't checked into this repository. The default `credhub` server's certificate chains to `credhub-v2-certs/server_ca_cert.pem`, generated by this repository's own `setup-credhub-v2-certs.sh`, so no `-k` is needed for it.)

When finished, stop and remove the containers with:

[source,bash]
----
$ docker-compose down
----

NOTE: The `pcfseceng/uaa`, `pcfseceng/credhub`, and `ampersand8/credhub` images are only published for `linux/amd64`. On Apple Silicon (arm64) hosts, Docker will emit a platform-mismatch warning and run them under emulation via Rosetta/QEMU — this is expected and safe to ignore, though the containers may take longer to start.

To generate the test jwt signing keys, ensure the `openssl` and https://carvel.dev/ytt/[`ytt`] tools are installed, then run the setup script:

[source,bash]
----
$ ./setup-uaa.sh
----

Run this before starting the containers, since `docker-compose.yml` mounts the generated `uaa.yml` into the UAA container. This repository already includes a generated `uaa.yml` and `config/` keypair, so you only need to re-run this script if you want to regenerate the signing keys.

To generate the CA certificate used to establish TLS trust for the default `credhub` server, ensure `openssl` is installed, then run:

[source,bash]
----
$ ./setup-credhub-v2-certs.sh
----

This writes a self-signed CA certificate and private key to `credhub-v2-certs/`. Both files are disposable, test-only material generated solely to satisfy TLS trust for a local Docker container — they protect nothing outside this test harness and are checked in for the same reason `config/privkey.pem` is: so the containers can start without a manual setup step for anyone who clones this repository. Automated secret scanners may still flag the private key as a detected secret; that's a false positive, not an indication of real exposure. You only need to re-run this script if you want to rotate the CA.

The default CredHub server's `pcfseceng/credhub` image looks for this CA cert/key at `/etc/server_certs` (mounted from `credhub-v2-certs/` in `docker-compose.yml`) and reuses it to sign a fresh leaf certificate on every container start, rather than generating a new throwaway CA each time — so the checked-in CA stays a valid trust anchor across restarts even though the leaf certificate itself changes.

To start only the default `credhub` server and its `uaa` dependency, without the legacy `credhub-v1` service, run `docker-compose up uaa credhub` instead.

The Gradle integration test suites (`spring-credhub-integration-tests`, `spring-credhub-reactive-integration-tests`) default to `https://localhost:9000`, so `./gradlew build -PintegrationTests --no-parallel` (see the root `CLAUDE.md`) exercises the default `credhub` server with no extra configuration, including `metadata`-related assertions that would otherwise be skipped via `assumeMetadataSupported()` against an older server.

To run those suites against the legacy `credhub-v1` server instead — e.g. to exercise pre-2.0 behavior like `mode`/`WriteMode` on writes, gated by `VersionInfo.isVersion1()` — override the client configuration when invoking Gradle:

[source,bash]
----
$ CREDHUB_SERVER=https://localhost:9001 \
  CREDHUB_CA_CERT=../credhub-server/credhub-v1-certs/server_ca_cert.pem \
  ./gradlew build -PintegrationTests --no-parallel
----
